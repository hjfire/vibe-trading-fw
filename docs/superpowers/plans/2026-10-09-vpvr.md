# VPVR（可视区成交量分布图）实现计划（推荐清单第 ⑤ 片）

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to execute this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在 `/pro-chart` 主图上加一个「量分布」开关：开＝把**当前可视区**的成交量按价格分成 100 档，画一张右锚横向直方图并高亮 POC 档与 70% 价值区，数值读在指标自己那行图例；关＝原样。**价格轴、`dataList`、图例真价、画线锚点、`pro-chart.drawings.v1`、分享码、`/multi-chart` 全部零影响。**

**Architecture:** 三个文件、三层。`lib/volumeProfile.ts` 是纯算术（`volumeProfile(bars, rows?) -> VolumeProfile` ＋ `valueAreaOf(profile, ratio?) -> ValueArea`），零 klinecharts import。`lib/vpvrChart.ts` 是库绑定层：注册一个**声明为空**的指标（`figures: []` ＋ `calc: () => []`），在模板的 `draw` 里现算现画横向直方图并返回 `true`，在 `createTooltipDataSource` 里给 POC/VAH/VAL 三行。`pages/ProChart.tsx` 只做四件事：偏好 state＋ref、`syncVpvr` 挂卸、进 effect 依赖数组、一个工具栏按钮——**`chartStyles` 一处都不改**。

**承重机制（为什么价格轴动不了）**：`YAxisImp.prototype.createRangeImp` 只把 `result[dataIndex][figure.key]` 里 `isNumber` 的值当价格折进 min/max（`frontend/node_modules/klinecharts/dist/index.esm.js:984`，折叠体 `:1045-1056`）。本片两把钥匙都不交：`figures` 空 ⇒ 折叠循环没有 key 可读；`result` 空 ⇒ 即便将来加了 key 也读不到数。而 `IndicatorView.prototype.drawImp` 调 `indicator.draw` 只问两道门——`indicator.visible`（`:8042`）与 `indicator.draw !== null`（`:8050`），**都不看 `result`/`figures` 长度** ⇒ 空声明指标的 `draw` 照样被调，这条路不是空想。

**Tech Stack:** React 19 + TypeScript（`strict: true`）+ Vite + Vitest（jsdom）+ Tailwind；图表库 klinecharts **10.0.3，未打补丁**（本计划不允许修改 `node_modules`）。

**Spec:** `docs/superpowers/specs/2026-10-09-vpvr-design.md` — 本计划是从它出发的论证，冲突时以 spec 为准。spec §〇 是「为什么不走档案原先预留的 overlay/`registerFigure` 通道」的三条证据，§二 是本轮逐条从 bundle 读出来的库事实（带坐标），§八 是未来函数边界与五步自查，§九 是判据清单。

**基线：** 分支 `feat/vpvr`，起点 `main` = `e89396d6`（含第④片 Heikin-Ashi `fcd55f69` ＋ 本片三笔 spec）。开工前基线读数由实现席**当场自测**，不引用本计划写下的任何数字：`npx tsc --noEmit -p tsconfig.json` 的 rc、`npx vitest run` 的文件/用例数、`python -X utf8 -m pytest tools/test_wiki_drift.py -q` 的条数。

## Global Constraints

每一条都约束所有 Task，值逐字取自 spec 与本仓既有纪律：

- **不 patch 库、不加依赖、不新增环境变量、不新增 locale 键**（面向用户的文案硬编码中文；指标图例行不走 i18n，与本仓 `均价: ` / `平均K线` 同做法）。
- **指标声明必须保持 `figures: []` ＋ `calc: () => []`**。这是本片价格轴不动的唯一结构保证；任何「顺手给 result 塞一行」的改动都会把像素或量能折进 y 轴 min/max，把标尺毒化。
- **像素量绝不进 `calc` 的返回值**（同上一条的另一面）：几何一律在 `draw` 里现算，`bounding`/`convertToPixel` 的结果不许挂到任何 figure key 上。

```ts
import { describe, expect, it } from "vitest";

import { volumeProfile, VPVR_ROWS, type ProfileBar } from "../volumeProfile";

/**
 * 手算向量（spec §九 第一条）。域 `[100, 104]`、4 档 ⇒ 档宽恰为 1。
 *
 * 逐根摊派（`进档量 = volume × 重叠 / (high - low)`）：
 *   A [100,102] 100 ⇒ 第 0 档 50、第 1 档 50
 *   B [102,104] 200 ⇒ 第 2 档 100、第 3 档 100（第 3 档右闭）
 *   C [101,103] 120 ⇒ 第 1 档 60、第 2 档 60
 *   D [104,104]  50 ⇒ 一字线，`floor` 给 4 ⇒ 钳进第 3 档
 * ⇒ 档位 `[50, 110, 160, 150]`、`totalVolume = 470`、`pocIndex = 2`。
 */
const VECTOR: ProfileBar[] = [
  { high: 102, low: 100, volume: 100 },
  { high: 104, low: 102, volume: 200 },
  { high: 103, low: 101, volume: 120 },
  { high: 104, low: 104, volume: 50 },
];

describe("volumeProfile 摊派", () => {
  it("手算向量：逐档、POC、总量、域极值、档边界全对上", () => {
    const p = volumeProfile(VECTOR, 4);
    expect(p.rows.map((r) => r.volume)).toEqual([50, 110, 160, 150]);
    expect(p.totalVolume).toBe(470);
    expect(p.pocIndex).toBe(2);
    expect(p.spanLow).toBe(100);
    expect(p.spanHigh).toBe(104);
    // 第 0..2 档是左闭右开的 1 宽格；末档右闭 ⇒ 它的 `high` 就是 `spanHigh`。
    expect(p.rows.map((r) => r.low)).toEqual([100, 101, 102, 103]);
    expect(p.rows.map((r) => r.high)).toEqual([101, 102, 103, 104]);
  });

  it("缺省档数是出厂的 100", () => {
    expect(volumeProfile(VECTOR).rows).toHaveLength(VPVR_ROWS);
  });

  it("一字线整量进包含该价的那一档，且不造出 NaN／Infinity", () => {
    // `high === low` 时摊派分母为 0——这是本片唯一造得出 `NaN` 的地方，所以它单独一条。
    const p = volumeProfile([{ high: 101, low: 101, volume: 7 }, ...VECTOR], 4);
    // 101 是第 1 档 `[101,102)` 的下界（下界含）⇒ 进第 1 档。
    expect(p.rows[1].volume).toBe(117);
    for (const row of p.rows) {
      expect(Number.isFinite(row.volume)).toBe(true);
    }
    expect(p.totalVolume).toBe(477);
  });

  it("末档右闭：`high === spanHigh` 的根钳进最后一档，一格量都不丢", () => {
    const p = volumeProfile(
      [
        { high: 104, low: 104, volume: 7 },
        { high: 100, low: 100, volume: 3 },
      ],
      4,
    );
    expect(p.rows.map((r) => r.volume)).toEqual([3, 0, 0, 7]);
    expect(p.rows[3].high).toBe(104);
    expect(p.totalVolume).toBe(10);
  });

  it("POC 并列取下（与价值区扩展的并列取上相反）", () => {
    // 域 [100,102]、2 档、档宽 1：两根各吃满一档 ⇒ 两档同量。
    const p = volumeProfile(
      [
        { high: 101, low: 100, volume: 10 },
        { high: 102, low: 101, volume: 10 },
      ],
      2,
    );
    expect(p.rows.map((r) => r.volume)).toEqual([10, 10]);
    expect(p.pocIndex).toBe(0);
  });

  it("摊派不丢量也不造量：逐档之和 === totalVolume（相对界，不是绝对位数）", () => {
    // 60 根、档宽不整除（域宽 12 / 100 档 = 0.12，二进制里不可精确表示）——浮点累加必然有噪声。
    // 这条同时钉住 §四 的钳位与摊派系数：漏一档或少一档都是 **O(一档的量)** 的错，
    // 而噪声是 O(总量 × 1e-14) 量级，两者差十个数量级，所以判相对界足够有杀伤力。
    // 为什么不用 `toBeCloseTo(…, 9)`：那是 5e-10 的**绝对**界，而本机 V8 实测 `rows = 100`
    // 时累加噪声 2.36e-9（实现席 2026-10-09 诊断），会被绝对位数随样本量级一起漂掉。
    const bars: ProfileBar[] = Array.from({ length: 60 }, (_, i) => ({
      low: 100 + (i % 10),
      high: 100 + (i % 10) + 3,
      volume: 1_000 + i,
    }));
    for (const rows of [2, 7, 8, VPVR_ROWS]) {
      const p = volumeProfile(bars, rows);
      const sum = p.rows.reduce((acc, r) => acc + r.volume, 0);
      expect(Math.abs(sum - p.totalVolume) / p.totalVolume).toBeLessThan(1e-11);
    }
  });
});

describe("volumeProfile 不看游标之后（spec §八 的算术形式）", () => {
  it("在 `k` 之后追加一根荒谬巨量，前 `k` 根的分布逐档不变", () => {
    const all: ProfileBar[] = Array.from({ length: 12 }, (_, i) => ({
      low: 100 + (i % 5) * 2,
      high: 100 + (i % 5) * 2 + 4,
      volume: 500 + i * 10,
    }));
    const k = 7;
    const prefix = volumeProfile(all.slice(0, k), 6);
    // 前缀的期望值**逐格写死**：7 根、域 [100,112]、6 档 ⇒ 档宽恰为 2（二进制精确），
    // 每根 `high - low` = 4 恰跨两档、各吃 1/2。
    //   档0 = 250+275 = 525   档1 = 250+255+275+280 = 1060   档2 = 255+260+280 = 795
    //   档3 = 260+265 = 525   档4 = 265+270 = 535            档5 = 270
    // 没有这几行字面值，下面那条「毒数组的切片与干净数组的切片相等」就是拿
    // `all.slice(0,7)` 与 `poisoned.slice(0,7)`（**内容逐元素相同、只换了数组对象**）互比，
    // 两侧一起错也照样绿。字面值把参照点钉死，等值那条才有意义。
    expect(prefix.spanLow).toBe(100);
    expect(prefix.spanHigh).toBe(112);
    expect(prefix.rows.map((r) => r.volume)).toEqual([525, 1060, 795, 525, 535, 270]);
    expect(prefix.totalVolume).toBe(3_710);
    expect(prefix.pocIndex).toBe(1);
    const poisoned: ProfileBar[] = [...all.slice(0, k), ...all.slice(k), { high: 9_999, low: -9_999, volume: 1e12 }];
    const fromPoisoned = volumeProfile(poisoned.slice(0, k), 6);
    expect(fromPoisoned).toEqual(prefix);
    // 这条**判的是什么**要说准：`poisoned.slice(0, k)` 与 `all.slice(0, k)` 内容相同，
    // 所以它判的是「无跨调用状态、对同一批根给出同一结果」——
    // 「切片本身取对没有」不在一个纯函数的判据面里，它归 Task 3 的 `profileOfChart`
    // （只有那里才决定喂进哪些根，判据是假 chart 逐索引那条）。
    // 阳性对照：毒根**确实有药**。把它真喂进去就必须改掉域与总量——否则上面那条相等
    // 可能只是在比一个对结果毫无影响力的输入（本仓 [[verify-scan-guard-false-green]] 的空集失效）。
    const full = volumeProfile(poisoned, 6);
    expect(full.spanLow).toBe(-9_999);
    expect(full.spanHigh).toBe(9_999);
    expect(full.totalVolume).toBe(1_000_000_006_660); // 1e12 ＋ 前 12 根的 6_660

    // 零头决定，那是浮点落点而不是判据——钉它就是把针交给最后一位舍入。
    // 回读**我们自己持有的**那个数组：前两次调用喂的是 `slice()` 出来的临时数组，
    // 实现若就地改写传入数组（`sort`／写脏某根），只有这一支抓得住——`full` 的域与总量
    // 对元素顺序不敏感，所以不读这一行，「不改调用方传入的数组」就只是注释里的声称。
    expect(poisoned.map((b) => b.volume)).toEqual([500, 510, 520, 530, 540, 550, 560, 570, 580, 590, 600, 610, 1e12]);
```

```ts
/**
 * VPVR 的纯算术层（推荐清单第⑤片，spec §四）。**零 klinecharts import**——
 * 与 `heikinAshi.ts` 同规：导入库的代价在测试里表现为必须 mock 整个模块，
 * 而这层的全部价值恰恰是「不看库也能逐格手算」。
 *
 * 三件事：分档（域取自**传入那一段**的极值）、把每根的量按价格重叠比例摊进档、找 POC。
 * 它不知道可视区、不知道游标、不知道像素——`spec §八` 那两条反未来函数判据之所以能
 * 只用一个纯函数写成，就是因为这些知识全都不在这里。
 */

export interface ProfileBar {
  /** 只声明真用到的三格：摊派读 `low`/`high`/`volume`，`open`/`close` 用不上。 */
  high: number;
  low: number;
  volume: number;
}

export interface ProfileRow {
  low: number;
  high: number;
  volume: number;
}

export interface VolumeProfile {
  rows: ProfileRow[];
  pocIndex: number;
  totalVolume: number;
  spanLow: number;
  spanHigh: number;
}

/** 出厂档数。写死而不是可配（spec §一：不做参数面板）。 */
export const VPVR_ROWS = 100;

export function volumeProfile(bars: readonly ProfileBar[], rows: number = VPVR_ROWS): VolumeProfile {
  if (bars.length === 0) {
    // 「空片」不是「算不出」：调用方（绑定层）在右侧留白区里会喂进空数组，
    // 这里交出一张全零档，绘制侧读到 `totalVolume === 0` 就一根都不画。
    return {
      rows: Array.from({ length: rows }, () => ({ low: 0, high: 0, volume: 0 })),
      pocIndex: 0,
      totalVolume: 0,
      spanLow: 0,
      spanHigh: 0,
    };
  }

  let spanLow = bars[0].low;
  let spanHigh = bars[0].high;
  for (const bar of bars) {
    if (bar.low < spanLow) spanLow = bar.low;
    if (bar.high > spanHigh) spanHigh = bar.high;
  }
  const rowHeight = (spanHigh - spanLow) / rows;

  const acc = new Array<number>(rows).fill(0);
  let totalVolume = 0;

  for (const bar of bars) {
    // 零量不进任何档，也不算异常：`market_routes.py:175-176` 会把整列补成 `0.0`，
    // `timeShare.ts:171-186` 早就把零量当真实分支处理。
    if (bar.volume === 0) continue;
    totalVolume += bar.volume;

    // 域塌成一个点（所有根同一价，含只有一根一字线）：档宽是 0，除法会炸。
    // 正解是全部进第 0 档——形状无从谈起，一张图也没有。
    if (rowHeight === 0) {
      acc[0] += bar.volume;
      continue;
    }

    const span = bar.high - bar.low;
    if (span === 0) {
      // 一字线／单点：整量进包含该价的那一档，不做除法。库自己在内置 EMV 里对同一
      // 形状单独立了分支（`dist:3998` `if (volume === 0 || high - low === 0)`）。
      // `Math.min(rows - 1, …)` 不是防御：`price === spanHigh` 时 `floor` 恰好给出行数，
      // spec §四 的「末档右闭」就是靠这一钳实现的。
      acc[Math.min(rows - 1, Math.max(0, Math.floor((bar.low - spanLow) / rowHeight)))] += bar.volume;
      continue;
    }

    // 区间按价格重叠比例摊派。循环上界用「档下界 < bar.high」而不是
    // `floor(bar.high …)`：后者在 `high` 正落在档边界上时会多带出一个**零重叠**档，
    // 而 `high === spanHigh` 那一档靠循环体里的右闭处理。
    let j = Math.max(0, Math.floor((bar.low - spanLow) / rowHeight));
    while (j < rows && spanLow + j * rowHeight < bar.high) {
      const rowLow = spanLow + j * rowHeight;
      // 末档右闭：它的上界直接取 `spanHigh`，不让 `spanLow + rows * rowHeight` 的
      // 浮点误差把最高那一小条量丢掉。
      const rowHigh = j === rows - 1 ? spanHigh : rowLow + rowHeight;
      const overlap = Math.min(bar.high, rowHigh) - Math.max(bar.low, rowLow);
      if (overlap > 0) acc[j] += (bar.volume * overlap) / span;
      j += 1;
    }
  }

  const out = new Array<ProfileRow>(rows);
  for (let j = 0; j < rows; j++) {
    out[j] = {
      low: spanLow + j * rowHeight,
      high: j === rows - 1 ? spanHigh : spanLow + (j + 1) * rowHeight,
      volume: acc[j],
    };
  }

  let pocIndex = 0;
  let best = acc[0];
  for (let j = 1; j < rows; j++) {
    // **严格大于** ⇒ 并列时先到的（低价档）赢。spec §四：POC 并列取下，
    // 与 §五 价值区扩展的并列取上**故意相反**——两条各有针，别顺手统一。
    if (acc[j] > best) {
      best = acc[j];
      pocIndex = j;
    }
  }

  return { rows: out, pocIndex, totalVolume, spanLow, spanHigh };
}
```

```ts
/** 出厂价值区比例（经典口径 70%）。 */
export const VPVR_VALUE_AREA_RATIO = 0.7;

export interface ValueArea {
  /** 闭区间，**含 POC 档自己**。 */
  lowIndex: number;
  highIndex: number;
  coverage: number;
}

/**
 * 经典 Volume Profile 价值区：从 POC 出发，每步比较**相邻的**上一档与下一档的量，
 * 吃掉较大的那一侧，直到累计 ≥ `ratio × totalVolume`。
 *
 * `ratio` 形参只为测试的两个边界（0 与 >1）而留，生产侧不传——它不是参数面板
 * （spec §一 否掉的是 UI 可调）。
 */
export function valueAreaOf(profile: VolumeProfile, ratio: number = VPVR_VALUE_AREA_RATIO): ValueArea {
  const rows = profile.rows;
  const total = profile.totalVolume;
  // `totalVolume === 0` 时 `coverage` 是 0 而不是 `0/0`；两条退化（空片／全零量）
  // 都从这一支出。
  if (total === 0) return { lowIndex: 0, highIndex: 0, coverage: 0 };

  const target = ratio * total;
  let lowIndex = profile.pocIndex;
  let highIndex = profile.pocIndex;
  let acc = rows[profile.pocIndex].volume;

  while (acc < target) {
    const canUp = highIndex + 1 < rows.length;
    const canDown = lowIndex - 1 >= 0;
    // 两侧都到头而仍未达标是**可达**情形（极端集中的分布＋高档数，或 `ratio > 1`），
    // 不是防御性代码：就地收摊返回当前区间。
    if (!canUp && !canDown) break;
    // 走哪一侧只由**边界**与两侧的档量决定，不用「越界记作 -1」的哨兵：哨兵要靠
    // 「档量非负」才必然输，而那是数据形状给的、不是这段代码给的。一旦有负量，越界那侧
    // 的 -1 反而赢，`highIndex` 就一路越界、`acc` 逐轮减下去，循环永不退出——页签冻死
    // 比算错一个数更糟。下面每一支都必然推进一个**存在的**下标，循环上界恒为
    // `rows.length`，与取值无关。
    // **并列取上侧**。注意这与 §四 的 POC 并列取下相反——一个「先到的赢」是扫描副产物，
    // 一个是扩展方向的选择，两条都是定死的口径。
    let takeUp: boolean;
    if (!canUp) takeUp = false;
    else if (!canDown) takeUp = true;
    else takeUp = rows[highIndex + 1].volume >= rows[lowIndex - 1].volume;
    if (takeUp) {
      highIndex += 1;
      acc += rows[highIndex].volume;
    } else {
      lowIndex -= 1;
      acc += rows[lowIndex].volume;
    }
  }

  return { lowIndex, highIndex, coverage: acc / total };
}
```

```ts
/**
 * `createRangeImp` 折叠体的六行镜像（`dist:984` ⇄ `:1045-1056`）：只把
 * `result[dataIndex][figure.key]` 里 `isNumber` 的值当价格。判「本指标声明能并进
 * 轴的价格集合是空集」。**判的是声明，不是库**——实地判据在 Task 6 的活体读数。
 */
function foldedPrices(
  figures: Array<{ key: string }>,
  result: Array<Record<string, unknown>>,
  len: number,
): number[] {
  const prices: number[] = [];
  for (let i = 0; i < len; i++) {
    const row = result[i];
    for (const figure of figures) {
      const value = row?.[figure.key];
      if (typeof value === "number") prices.push(value);
    }
  }
  return prices;
}
```

```ts
import { registerIndicator, type Chart, type KLineData, type YAxis } from "klinecharts";

import { valueAreaOf, volumeProfile, VPVR_ROWS, type ProfileBar, type VolumeProfile } from "./volumeProfile";

/**
 * VPVR 的库绑定层（推荐清单第⑤片，spec §三/§六）。
 *
 * 走的是 `registerIndicator` 的 `draw` 通道，不是档案原先给第⑤片预留的
 * overlay/`registerFigure` 通道（spec §〇 三条证据，其中 `serializeDrawings`
 * 没有工具名白名单、走 overlay 会往 `pro-chart.drawings.v1` 写一条读侧认不出的假画线，
 * 是决定性那条）。
 *
 * 三件承重的事：
 *
 * 1. **声明是空的**：`figures: []` 且 `calc: () => []`。`YAxisImp.createRangeImp`
 *    （`dist:984`，折叠体 `:1045-1056`）只把 `result[dataIndex][figure.key]` 里的数值
 *    当价格折进 min/max ⇒ 两把钥匙都不交，价格轴就结构上动不了。这不是「不需要轴」的
 *    侥幸：第④片是靠**把** HA 高低挂到 figure key 上免掉裁切，同一条规则的用法两面。
 * 2. **`draw` 照样会被调**：`IndicatorView.drawImp` 的门只有 `indicator.visible`
 *    （`:8042`）与 `indicator.draw !== null`（`:8050`），都不看 result／figures 的长度。
 * 3. **`return true` 的理由要说准**：本片 figures 为空，返回 `false` 也**不会**多画
 *    任何东西（`prepareIndicatorFigures` 交回空数组）。`true` 换到的是省掉
 *    `eachChildren` 的逐根空遍历，以及与 `haDraw` 同一份契约——不是「防止重复绘制」。
 *
 * 图例只有本指标自己那一行（POC/VAH/VAL）：`createTooltipDataSource` 返回的 `legends`
 * 整段替换由 figures 生成的默认行（`IndicatorTooltipView.getIndicatorTooltipData`，
 * `dist:7241` ⇄ 覆写点 `:7334`），而 figures 本来就是空的。
 *
 * **单测里的图例字符串 ≠ 屏幕上的字形**：库在覆写前对每格 `value.text` 跑
 * `decimalFold.format(thousandsSeparator.format(...))`（`:7329-7331`，`"-"` 那格过不了
 * 它前面 `isNumber` 那道门，原样留着），千分位默认 `sign: ','`（`:13095`，本仓没有任何
 * 地方覆写它）。所以价格 ≥ 1000 时屏幕上那格是 `1,234.56`。图例画在 canvas 上、DOM 读不到，
 * 故 Task 6 的判据分两层：值从 `getIndicators({name:'VPVR'})[0].createTooltipDataSource({chart})`
 * 读回与 oracle 逐字比，字形用库自己的 `getThousandsSeparator()`／`getDecimalFold()` 复现
 * （spec §二·4/4b）。逗号那一格是**预期**，不是缺陷。

export const VPVR_SHORT_NAME = "量分布";

export const VPVR_PREFS_KEY = "pro-chart.vpvr.v1";

/**
 * 三枚半透明色：底下的蜡烛要读得出来，所以不是实心。不读 `chart.getStyles()`、
 * 不随主题变——与第④片 `colorsOf` 同一个取舍（接主题要动 `chartStyles`，
 * 而那片有两张既有钉挡着，spec §一 末条）。
 */
export const VPVR_COLOR_BASE = "rgba(66, 165, 245, 0.22)";
export const VPVR_COLOR_VALUE_AREA = "rgba(66, 165, 245, 0.38)";
export const VPVR_COLOR_POC = "rgba(255, 167, 38, 0.55)";

/** 最大档占 pane 宽度的比例（右锚向左生长的上限）。 */

/**
 * VPVR 是否真的在图上。单一谓词：Task 4 的挂卸侧与按钮态都读它，不再各写一遍
 * `on && !timeShare`（形状照 `lib/chartView.ts` 里那几枚周期谓词，不是「样式侧也读」——
 * 本片不写样式键，`chartStyles` 一格都不碰）。分时是面积线（`candle.type === "area"`），
 * 没有 `[low, high]` 区间可摊 ⇒ 一律压掉。

export function vpvrActive(on: boolean, timeShare: boolean): boolean {

/**
 * 本片只用到 chart 的这两格；写成结构化类型让单测能交最小替身。
 *
 * `getDataList` 的返回格交的是「真被读的三格」而不是整个 `KLineData[]`：库把
 * `open`/`close` 也定成必填（`dist/index.d.ts:97-105`），而 `ProfileBar` 读的就是
 * `high`/`low`/`volume` 这三格——替身按 `Pick<Chart, "getDataList" | "getVisibleRange">`
 * 写会交不出开收两格（TS2345），按这三格写则真 `Chart` 仍结构上可赋进来（`KLineData`
 * 是它的超集），Task 4 那边传的仍是库的 `Chart`。
 */
type ChartView = {
  getDataList: () => ReadonlyArray<Pick<KLineData, "high" | "low" | "volume">>;
  getVisibleRange: Chart["getVisibleRange"];
};

/**
 * 可视区切片 → 分布，**唯一实现**（`vpvrDraw` 与 `vpvrTooltipDataSource` 都调它；
 * 各写一遍就是本仓禁止的重复逻辑）。
 *
 * `realTo` 是排他的（库自己的循环 `for (i = realFrom; i < realTo; i++)`），再与
 * `dataList.length` 取小：右侧留白区里有像素但没有数据。`bar.volume ?? 0` 是**类型要求**
 * （`KLineData.volume?: number`，`dist/index.d.ts:97-105`），不是防御。
 */
export function profileOfChart(chart: ChartView): VolumeProfile {
  const dataList = chart.getDataList();
  const { realFrom, realTo } = chart.getVisibleRange();
  const from = Math.max(0, realFrom);
  const to = Math.min(realTo, dataList.length);
  const bars: ProfileBar[] = [];
  for (let i = from; i < to; i++) {
    const bar = dataList[i];
    bars.push({ high: bar.high, low: bar.low, volume: bar.volume ?? 0 });
  }
  return volumeProfile(bars, VPVR_ROWS);
}

interface DrawCtx {
  // 取库自己的口径而不是 `string`：本地收窄会把 `registerIndicator` 交进来的那份
  // `fillStyle: string | CanvasGradient | CanvasPattern` 挡在外面，调用点就只靠
  // `as unknown as` 全量重断言（第④片 R11 的教训）。
  fillStyle: CanvasRenderingContext2D["fillStyle"];
  fillRect(x: number, y: number, w: number, h: number): void;
}

interface DrawParams {
  ctx: DrawCtx;
  bounding: { width: number; height: number };
  chart: ChartView;
  // 不需要 `xAxis`：横向位置由 `bounding.width` 给（右锚）。不需要 `getBarSpace`：
  // 档高度来自价格像素，跟 bar 宽无关。
  yAxis: Pick<YAxis, "convertToPixel">;
}

interface TooltipParams {
  chart: ChartView;
}

/**
 * 一根档 = 一个矩形，右锚向左生长。
 *
 * `yTop` 取的是档的**上界价格**（`row.high`）——价格越高像素越小，所以它是矩形顶边；
 * `Math.max(1, yBottom - yTop)` 保证 100 档配窄 pane 时（每档不足 1px）仍看得见。
 * 零档一根都不画（含 `totalVolume === 0` 的整张图）：给它留一个矩形会把「没有分布」
 * 画成「一条平线」。
 */
export function vpvrDraw({ ctx, bounding, chart, yAxis }: DrawParams): boolean {
  const profile = profileOfChart(chart);
  const area = valueAreaOf(profile);
  const rows = profile.rows;

  let maxVolume = 0;
  for (const row of rows) {
    if (row.volume > maxVolume) maxVolume = row.volume;
  }
  if (maxVolume === 0) return true;

  const maxLen = bounding.width * VPVR_MAX_WIDTH_RATIO;
  for (let j = 0; j < rows.length; j++) {
    const row = rows[j];
    if (row.volume <= 0) continue;
    const len = maxLen * (row.volume / maxVolume);
    const yTop = yAxis.convertToPixel(row.high);
    const yBottom = yAxis.convertToPixel(row.low);
    // 优先级：POC 档 > 价值区档 > 基础档。POC 档**总是**价值区的成员（扩展从它出发），
    // 所以这一格顺序不是风格问题——反过来的话 POC 在图上就没有自己的颜色了。
    ctx.fillStyle =
      j === profile.pocIndex
        ? VPVR_COLOR_POC
        : j >= area.lowIndex && j <= area.highIndex
          ? VPVR_COLOR_VALUE_AREA
          : VPVR_COLOR_BASE;
    ctx.fillRect(bounding.width - len, yTop, len, Math.max(1, yBottom - yTop));
  }
  return true;
}

/**
 * 图例那一行：三个**价格**（POC 档中点、VAH 档上界、VAL 档下界），不是量。
 *
 * 量到不了文字这一层——前端的 `volume` 没有单位（spec §一）。`totalVolume === 0` 时
 * 三格都读 `"-"` 而不是算出 `0.00` 骗人：那是「没有分布」，不是「分布在 0」。
 * 标题用中文字面量、不走 i18n：库只对**蜡烛**图例的 title 再跑一次 `i18n`
 * （`dist:7678`），指标这一行走不到，`均价: ` 同例。
 */
export function vpvrTooltipDataSource({ chart }: TooltipParams) {
  const profile = profileOfChart(chart);
  const area = valueAreaOf(profile);
  const empty = profile.totalVolume === 0;
  const pocRow = profile.rows[profile.pocIndex];
  return {
    name: VPVR_SHORT_NAME,
    calcParamsText: "",
    features: [],
    legends: [
      { title: "POC: ", value: empty ? "-" : ((pocRow.low + pocRow.high) / 2).toFixed(2) },
      { title: "VAH: ", value: empty ? "-" : profile.rows[area.highIndex].high.toFixed(2) },
      { title: "VAL: ", value: empty ? "-" : profile.rows[area.lowIndex].low.toFixed(2) },
    ],
  };
}

/**
 * 注册守卫：`registerIndicator` 改的是全局表，每次切换都注册会在图表活着的时候反复覆写。
```

```tsx
   * `isStack` (the second argument) is load-bearing in a way it is not for HA: the real
   * `addIndicator(create, isStack)` removes every other indicator on the pane when it is
   * falsy. HA survives that by accident of ordering; here the pair HA-plus-VPVR is asserted
   * side by side (`ProChartVpvr.test.tsx`, 共挂那条), so dropping it goes red.
   *
   * Unmounting is `removeIndicator({ name })` even when nothing is mounted — the orphan-pane
   * sweep explicitly skips the candle pane (dist 15332), so a no-match call cannot take the
   * main chart down.
   */
  const syncVpvr = (chart: Nullable<Chart>, on: boolean) => {
    if (!chart) return;
    if (!on) {
      chart.removeIndicator({ name: VPVR_NAME });
      return;
    }
    ensureVpvrIndicator();
    const live = chart.getIndicators({ name: VPVR_NAME });
    live.slice(1).forEach((extra) => chart.removeIndicator({ id: extra.id }));
    if (live.length === 0) {
      chart.createIndicator({ name: VPVR_NAME, paneId: MAIN_PANE_ID }, true);
    }
  };
```

**页内独立 oracle（全文粘进 REPL，不许 import 生产模块）**。它是「先造 rows+1 个边界数、再对每根逐档求 `min/max` 重叠」的形状，与生产 `volumeProfile` 那条 `while (j < rows && spanLow + j*rowHeight < bar.high)` 的游标循环**刻意不同形**——同形的 oracle 会把同一个越界错误抄两遍，就成了自我确认。

```js
window.__vp = (bars, rows = 100) => {
  let lo = Infinity, hi = -Infinity, total = 0;
  for (const b of bars) {
    if (b.low < lo) lo = b.low;
    if (b.high > hi) hi = b.high;
    total += b.volume || 0;
  }
  if (bars.length === 0 || total === 0 || !(hi > lo)) {
    return { empty: true, poc: "-", vah: "-", val: "-", total };
  }
  const step = (hi - lo) / rows;
  const edge = Array.from({ length: rows + 1 }, (_, i) => (i >= rows ? hi : lo + i * step)); // rows+1 个边界数，末档右闭直接取 hi
  const acc = new Array(rows).fill(0);
  for (const b of bars) {
    const v = b.volume || 0;
    const span = b.high - b.low;
    if (span === 0) {
      let k = 0;
      while (k < rows - 1 && b.low >= edge[k + 1]) k++;
      acc[k] += v;
      continue;
    }
    for (let i = 0; i < rows; i++) {
      const ov = Math.min(b.high, edge[i + 1]) - Math.max(b.low, edge[i]);
      if (ov > 0) acc[i] += (v * ov) / span;
    }
  }
  let poc = 0;
  for (let i = 1; i < rows; i++) if (acc[i] > acc[poc]) poc = i;
  // 价值区：并列吃上侧，与上面 POC 的并列吃下侧相反（spec §五）
  // 这里**故意**保留 -1 哨兵，不要顺手改成与生产同形：oracle 是一次性的页内探针，有 guard
  // 兜住终止性、且只喂真实根（非负）；生产侧没有 guard，所以它的终止性必须由边界结构自己
  // 保证（`valueAreaOf` 的注释记着这条理由）。两侧循环形状不同，正是判据取「三个 `.toFixed(2)`
  // 字符串逐字相等」而不是「同形比对」的原因之一。
  let low = poc, high = poc, inVa = acc[poc], guard = 0;
  while (inVa < total * 0.7 && guard++ < rows) {
    const up = high + 1 < rows ? acc[high + 1] : -1;
    const dn = low - 1 >= 0 ? acc[low - 1] : -1;
    if (up < 0 && dn < 0) break;
    if (dn > up) { low--; inVa += acc[low]; } else { high++; inVa += acc[high]; }
  }
  const f = (x) => x.toFixed(2);
  return {
    empty: false,
    poc: f((edge[poc] + edge[poc + 1]) / 2),
    vah: f(edge[high + 1]),
    val: f(edge[low]),
    cov: inVa / total, // 价值区实际覆盖率，判「70% 落点分歧」用
    total,
  };
};
```

> **oracle 声明形状取证（Task 6 现场更正，本节下面那三条读数判据不受影响）**：首版把边界写成**箭头函数** `const edge = (i) => ...`，末尾三格却用**下标**读 `edge[poc] / edge[poc+1] / edge[high+1] / edge[low]`——函数对象上数字下标恒 `undefined`，全文逐字粘进页面即抛 `TypeError: Cannot read properties of undefined (reading 'toFixed')`。改成与本节开头「先造 rows+1 个边界数」一致的 **`rows+1` 长度数组**（`Array.from`），两处 `edge(i)` 调用形式同步改下标。语义没动：末档右界仍取 `hi`、中间档仍等宽，形状仍是「rows+1 边界 ＋ 逐档 `min/max` 重叠」，与生产那条游标循环**仍然不同形**（不塌回自我确认）；数值判据仍是「三个 `.toFixed(2)` 串逐字相等」，没有因这一改放宽。
