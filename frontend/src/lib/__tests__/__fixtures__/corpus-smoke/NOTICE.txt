Community Pine corpus — smoke regression slice
=============================================

Provenance
----------
Every .pine file under this folder (and the larger local-only set that
frontend/scripts/corpus/fetchPineCorpus.mjs downloads into
src/lib/__tests__/__fixtures__/corpus/) is copied VERBATIM from the public
repository:

    everget/tradingview-pinescript-indicators   (branch: master)

Author: Alex Orekhov (everget). These are real TradingView indicators written
by someone else — that is exactly why they are used here: compatibility
acceptance has to run on code we did not author, not only on our own scripts.

Why a curated slice is committed
--------------------------------
The full corpus (210 files) is fetched locally on demand and is NOT committed
(it is external, changeful content). This 53-file slice (41 everget v3/v4 + 12
from the v6 corpus below) covers the categories
that currently pass (bands_and_channels / movings / oscillators / statistics /
trailing_stops / volatility / volume / highlighters) and is pinned by
src/lib/__tests__/pineCorpusSmoke.test.ts as a permanent regression: any engine
change that stops compiling/running one of them must fail the build.

The slice was widened from 18 to 26 alongside the legacy-builtin work, so the
gate now also pins the constructs those engine gaps used to reject: trig (`asin`
/ `atan` in gaussian_filter, ehlers_mesa_adaptive_moving_averages), `linreg`
(least_squares_moving_average), `percentrank` (stochastic_connors_rsi),
`percentile_nearest_rank` + legacy `color(...)` + bare colour globals
(interquartile_range_bands, negative_volume_index), a bare v2 style constant
(percent_volume), and legacy unprefixed `security(...)` MTF
(dividends_per_share_dps_yearly).

The slice was widened again from 26 to 32 alongside the multi-line expression
continuation work (the lexer now also treats a line that OPENS with an operator
`? : + - * / % ^ < > == != <> and or to by` as a wrapped continuation). These
six scripts lean on that rule — folded ternaries and operator-led arithmetic
across lines inside recursive digital filters — so they lock the merge against a
future regression, and the folded form is proven byte-for-byte identical to the
equivalent single-line expression by pineContinuation.test.ts:

    movings/butterworth_filter.pine
    movings/ehlers_super_smoother_filter.pine
    movings/fibonacci_weighted_moving_average.pine
    movings/henderson_weighted_moving_average.pine
    oscillators/rainbow_oscillator.pine
    statistics/z_score.pine

The slice grew from 32 to 35 with two real Pine built-ins added to close the
corpus runtime_abort backlog — `ta.valuewhen(condition, source, occurrence)` and
`offset(series, n)` (the right-shift series helper, distinct from plot's
cosmetic `offset=`). These three scripts exercise them and their folded values
are hand-checked against deterministic bars by pineSeries.test.ts:

    oscillators/gator_oscillator.pine              (offset)
    statistics/roi_return_on_investment.pine       (valuewhen)
    statistics/ytd_year_to_date_percent_return.pine (valuewhen)

The slice grew from 35 to 41 after closing five more real engine gaps that left
these otherwise-complete indicators plotting nothing but na. Each is now
numerically cross-checked against deterministic bars by pineBuiltins.test.ts
(single-vs-two-arg `highest`/`lowest`, `input(..., type=source)` binding to the
live series, string- and numeric-`options=` enums, and per-call-site isolation
of stateful builtins inside a user helper called twice):

    movings/fractal_adaptive_moving_average.pine    (one-arg highest/lowest)
    volatility/gopalakrishnan_range_index.pine      (one-arg highest/lowest)
    movings/vidya_variable_index_dynamic_average.pine (input source + numeric enum)
    bands_and_channels/stoller_average_range_channels.pine (string enum input)
    oscillators/center_of_gravity_oscillator.pine    (string enum input)
    movings/hampel_filter.pine                       (per-call-site builtin state)

(gaussian_filter.pine, pinned earlier, was silently broken by the first pass of
the string-enum fix — a numeric `options=[1,2,3,4]` input was mis-routed to the
string branch and blanked its `plot`. The type/defval/options string-ness check
now keeps numeric enums numeric, so the committed gate caught the regression.)

The eight scripts still aborting are NOT engine gaps we papered over: they
reference variables never declared anywhere (`n`, `period`, `accdist`, `pvt`),
which TradingView also rejects. Leaving them red is the honest outcome —
implementing a builtin only to watch a broken script emit a plausible-but-wrong
number would be worse than an accurate error.

Defect J closed one more real gap: `array.join(id, separator, index_from?,
index_to?)` was missing from ARRAY_OPS (it concatenates the elements with the
separator inserted only *between* them, an exclusive `[from, to)` subset when
indices are given, `index_to` default running to the end). This cleared
`utils/unit_testing_framework.pine`, which called it and aborted; everget
runtime_abort fell 9 -> 8 (88.6% held — ok unchanged). It now runs to
completion but plots nothing (it is a label/table-only unit-test harness), so it
moved to `no_output`, NOT into the pinned slice: the smoke gate asserts a real
plotting output, and a script that faithfully produces none must not be faked
into the green set. Verified against exact TV strings by pineBuiltins.test.ts
(separator between-only, empty separator, integer elements rendered without
`.0`, and the exclusive index subset `join(a, "", 1, 3) == "23"`).

Second source: Pine v6 (mihakralj)
----------------------------------
The everget set is all v3/v4, so to surface modern-syntax gaps a second,
local-only corpus was added: 410 standalone v6 indicators copied VERBATIM from

    mihakralj/pinescript   (branch: main)

Author: mihakralj, MIT-licensed (per-file MIT header preserved); fetched by the
same script via CORPUS_MANIFEST=pine-community-v6.manifest.json into
__fixtures__/corpus-v6/. Measured by pineCorpusReport with PINE_CORPUS_DIR.
The engine passes 97.6% of them (400/410) — v6 typed function signatures, array
<T> generics, switch, and request.security already work.

The biggest v6 gap closed (defect G) is the comma STATEMENT SEPARATOR: Pine
lets several statements share one line when separated by a top-level comma
(`sum1 += a, sum2 += b`). The parser's `=` declaration form already handled
this, but compound (`+= -=`), `:=` reassignment, and bare call statements did
not — `endOfStmt` rejected the trailing comma as "extra content". Unifying all
assignment/expression forms in pineLang.parseAssignOrExprList flipped 15 v6
scripts from compile_error to ok (92.4% -> 96.1%) with everget unchanged at
88.6% (everget has zero compile_errors, so no passing line ever reached that
comma path — the regression is provably contained). These six v6 scripts lean
on the comma separator and are pinned byte-for-byte (SHA-checked) as a gate:

    v6/statistics/correlation.pine   (var + `+=`/`-=` accumulators, request.security)
    v6/statistics/beta.pine          (comma-joined compound accumulators)
    v6/statistics/zscore.pine        (comma-joined var decls)
    v6/oscillators/trix.pine         (triple-EMA, comma `var` list)
    v6/oscillators/smi.pine          (commodity channel, comma decls)
    v6/numerics/jerk.pine            (comma-joined `:=` reassignments)

The two remaining v6 compile errors are NOT pinned. Once the array.join,
bitwise, and matrix gaps were closed (defects J, K and L), each residual is a
broken source TradingView also rejects — never a contorted parser bending to
make one file green:

  - `apo.pine` omits a comma between two `var` decls on one line (`= na var
    float ...`) — invalid Pine, so it stays honestly red.
  - `fft.pine` first failed on v6 bitwise operators, now fixed (defect K); its
    NEXT error is C-style return-type-prefixed function defs (`int ilog2(int n)
    =>`, `void fft_inplace(...) =>`). Pine's function grammar is `name(params)
    =>` with NO return-type prefix (TV type-system docs: "no 'void' keyword
    exists in Pine Script"), and none of the other 619 corpus scripts writes
    it — so fft is a broken source TradingView also rejects, left red rather
    than bending the parser to accept non-Pine syntax.

`mlp.pine` was the third residual and is now OK (defect L): it is valid Pine and
only lacked the `matrix.*` namespace plus a `type matrices` UDT with matrix
fields; both are implemented and reconciled, lifting v6 from 97.6% to 97.8%.

defect K (v6 bitwise operators) — `& | << >> ~` were unrecognised characters
(`无法识别的字符 "|"`). They are valid Pine v6 operators, so the lexer now
accepts `&`/`|` as single ops and `~` as unary, and the parser reassembles
adjacent `<`/`>` into `<<`/`>>` at expression level — deliberately NOT merging
them into the multi-char token table so nested generic closings
(`array<array<float>>`) keep lexing as separate `>` tokens. Precedence is the
C-like order (shift below additive, `&`/`|` below comparison above logical
`and`/`or`); operands truncate to int with na propagation. Bitwise XOR (`^^`) is
left out: Pine's `^` is exponentiation here and the authoritative `^^` precedence
is unconfirmed, so inventing it would be speculation. pineBuiltins.test.ts pins
exact integer results for every operator plus two precedence discriminators and
a radix-2 bitReverse loop — the honest reconciliation, since the only corpus
file that uses bitwise (fft) is itself broken for a different reason.

defect L (v6 matrix namespace + UDT integration) — `mlp.pine` (a self-training
perceptron) is the only corpus user of `matrix.*` and of a UDT holding matrix
fields. Four real gaps stood between it and `ok`, all fixed and reconciled:

  - A new `pineMatrix.ts` (7 ops: `new`/`get`/`set`/`rows`/`columns`/`copy`/
    `mult`) routes free-form like `map.*`. A matrix reuses the `V[]` value type
    as an array-of-row-`V[]`s, so `readSeries` hands the live array back by
    reference and `matrix.set` mutates in place across bars and aliases.
  - `obj.field := v` on a UDT record used to write a standalone dotted slot that
    only read back under that exact name; the record's own field stayed `na`, so
    a matrix passed to another function vanished. Now it mutates the `@udt:`
    record slot in place (Pine passes records by reference).
  - `type` field lines captured the LAST identifier as the name, so a defaulted
    field `matrix<float> l0 = na` got the name `na`. Fixed to the last identifier
    BEFORE `=`.
  - A UDT name in declaration position (`var matrices w = na`) is not a built-in
    TYPE_WORD, so `w` was trailing junk; and v6 `method name(Type this) =>` heads
    were unrecognised. Both handled — and the `Type name = …` drop is guarded by
    the following `=` so it never eats an operator-keyword line like
    `annualize and …` (Pine lexes `and`/`or`/`not` as identifiers).
  - mlp's final blocker was the bidirectional line-continuation rule folding a
    `-1.0` ELSE-branch body into the `if` condition (`x <= -20.0` newline `-1.0`
    merged into one expression). Now a block-header line (`if`/`else`/`for`/
    `while`/`switch`) whose next line opens with an ARITHMETIC operator does not
    merge — the successor is a block body, not a wrapped operand. Logical/relational
    wraps (`and volume > 0`) and assignment wraps (`q = 2` / `+ 3`) are untouched.

pineBuiltins.test.ts pins exact 2x2 and 1xK·KxM products, dimension reads, na
default cells, in-place set/get, copy independence, the record-by-reference field
write, and a `method`-head transform — the numeric reconciliation, since the
acceptance bar (mlp → ok) only proves it runs, not that the math is right.

Two more real v6 built-in gaps (defects H and I) then cleared six runtime
aborts, lifting v6 from 96.1% to 97.6% with everget held at 88.6%:

  - `ta.sum(source, length)` was never wired into the ta.* table even though
    the rolling-sum primitive (`sumStep`) already existed internally (used by
    MFI / Chande). Theil's U / WMAPE / WRMSE aborts were only a missing name.
  - `array.fill(a, value, index_from?, index_to?)` was missing entirely; the
    documented behaviour is whole-array fill when no index is given (the seeding
    idiom RGMA / ZLEMA / Stoch use), and a `[from, to)` run otherwise. Added to
    ARRAY_OPS so both the free (`array.fill(buf, x)`) and method (`buf.fill(x)`)
    forms route through it.

Both are numerically cross-checked by pineBuiltins.test.ts (ta.sum equals a
hand-summed window and equals `ta.sma * length`; array.fill seeds all slots and
honors the exclusive index range). These six v6 scripts lean on them and are
pinned byte-for-byte (SHA-checked) as a gate:

    v6/errors/theilu.pine           (ta.sum over squared-error series)
    v6/errors/wmape.pine            (ta.sum)
    v6/errors/wrmse.pine            (ta.sum)
    v6/oscillators/stoch.pine       (array.fill whole-buffer seed)
    v6/trends_IIR/rgma.pine         (array.fill seed + array.set)
    v6/trends_IIR/zltema.pine       (array.fill seed)

CORRECTION (this pass, evidence-driven): the earlier note here claimed
`cfb.pine`'s `hlccN` and `sam.pine`'s `ji` were "broken sources TradingView
also rejects". That was wrong and has been re-verified against TradingView's
own documentation, so both were real engine gaps and are now fixed rather than
excused:

  - `hlcc4` is a documented Pine source, `(high + low + close + close) / 4`,
    introduced with v4/v5. The engine never exposed it (and its `hlc3` was
    mis-written as `(high + low*2)/3` instead of `(high + low + close)/3`).
    Both are now correct and exact-value pinned.
  - `sam.pine`'s `float ji = f(ji[1])` is the legitimate v5/v6 recursive-series
    idiom (a declaration reading its own prior-bar history); v3's "removed
    self-reference" only barred offset-0 self-reference, not `ji[1]`. The
    runtime now lets a declaration's initializer read its own name's history as
    `na` on bar 0 (via a pending-set consulted only by `readBack`), so `sam`
    runs. A bare offset-0 self-reference still aborts, matching TradingView.

The same pass cleared the remaining legacy bare-name aborts on the everget
side, all version-gated so v5/v6 keep honest aborts: `n` was the v3 bar-index
(superseded by `bar_index` in v4) and `accdist`/`pvt` (plus `obv`/`nvi`/`pvi`)
were v3/v4 bare series that moved under `ta.*` in v5 — an undefined bare
identifier with `ver <= 4` now resolves through the matching `ta.*` state
machine, with a per-bar memo so a read-many-times name still advances its
accumulator once per bar.

After these fixes the v6 aborts that remain are NOT semantic gaps and stay
honestly red, unfixed by inventing behavior: `hurst.pine` and `cfb.pine` (once
`hlcc4` resolves) both trip the engine's compute-budget guard (OP_LIMIT 2.5e7)
on genuinely O(length^2)-per-bar nested recomputation — a performance limit on
heavy scripts, not a missing construct. On the everget side the two residual
aborts are both `period` (a bare `security(..., period, ...)`): TradingView
itself rejects an undeclared `period` (the correct spelling is
`timeframe.period`), so accepting it would mean inventing non-existent
semantics — left honestly red.

Net reconciliation (fresh re-run, not stale): everget runtime_abort 8 -> 2, ok
187 -> 193, pass-rate 88.6% -> 91.9%; v6 ok 402 -> 403 (`sam` cleared),
runtime_abort 3 -> 2 (both compute-budget), pass-rate 98% -> 98.3%. Separately,
the v6 "booleans cannot be na" comparison rule (`na > x` resolves to a definite
false/true, never `na`, so a warmup bar no longer poisons a `var` accumulator —
Chande `cmo`/`supertrend`) was gated to `ver >= 6` inside `binary()`, lifting
one ok in each corpus; pre-v6 warmup `na` blanking is untouched. None of these
newly-green scripts is pinned into this smoke slice unless it emits real
numeric output.

The remaining `no_output` scripts are likewise NOT pinned, and not because the
currently-unsupported drawing is trivially fixable: the highlighters only emit
`bgcolor`, the research/statistics helpers redraw chart types or fill a `table`
(the primitive plot/markers the engine intentionally ignores), and `supertrend`
feeds a `ta.atr` warmup `na` into a `var int dir` accumulator whose only escape
requires `dir == 1` / `dir == -1` — under faithful Pine `na` propagation `dir`
stays `na`, which is what the engine does. Bending the logical/ternary `na` rules
to resurrect that accumulator would be inventing non-standard semantics with
blast radius across every other script, so it is left honestly red.
