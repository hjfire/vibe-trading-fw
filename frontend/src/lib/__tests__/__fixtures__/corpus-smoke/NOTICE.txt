Community Pine corpus — smoke regression slice
=============================================

Provenance
----------
Every .pine file under this folder (and the larger local-only set that
frontend/scripts/corpus/fetchPineCorpus.mjs downloads into
src/lib/__tests__/__fixtures__/corpus/) is copied VERBATIM from the public
repository:

    everget/tradingview-pinescript-indicators   (branch: master)

Author: Alex Orekhov (everget). These are real TradingView indicators written
by someone else — that is exactly why they are used here: compatibility
acceptance has to run on code we did not author, not only on our own scripts.

Why a curated slice is committed
--------------------------------
The full corpus (210 files) is fetched locally on demand and is NOT committed
(it is external, changeful content). This 35-file slice covers the categories
that currently pass (bands_and_channels / movings / oscillators / statistics /
trailing_stops / volatility / volume / highlighters) and is pinned by
src/lib/__tests__/pineCorpusSmoke.test.ts as a permanent regression: any engine
change that stops compiling/running one of them must fail the build.

The slice was widened from 18 to 26 alongside the legacy-builtin work, so the
gate now also pins the constructs those engine gaps used to reject: trig (`asin`
/ `atan` in gaussian_filter, ehlers_mesa_adaptive_moving_averages), `linreg`
(least_squares_moving_average), `percentrank` (stochastic_connors_rsi),
`percentile_nearest_rank` + legacy `color(...)` + bare colour globals
(interquartile_range_bands, negative_volume_index), a bare v2 style constant
(percent_volume), and legacy unprefixed `security(...)` MTF
(dividends_per_share_dps_yearly).

The slice was widened again from 26 to 32 alongside the multi-line expression
continuation work (the lexer now also treats a line that OPENS with an operator
`? : + - * / % ^ < > == != <> and or to by` as a wrapped continuation). These
six scripts lean on that rule — folded ternaries and operator-led arithmetic
across lines inside recursive digital filters — so they lock the merge against a
future regression, and the folded form is proven byte-for-byte identical to the
equivalent single-line expression by pineContinuation.test.ts:

    movings/butterworth_filter.pine
    movings/ehlers_super_smoother_filter.pine
    movings/fibonacci_weighted_moving_average.pine
    movings/henderson_weighted_moving_average.pine
    oscillators/rainbow_oscillator.pine
    statistics/z_score.pine

The slice grew from 32 to 35 with two real Pine built-ins added to close the
corpus runtime_abort backlog — `ta.valuewhen(condition, source, occurrence)` and
`offset(series, n)` (the right-shift series helper, distinct from plot's
cosmetic `offset=`). These three scripts exercise them and their folded values
are hand-checked against deterministic bars by pineSeries.test.ts:

    oscillators/gator_oscillator.pine              (offset)
    statistics/roi_return_on_investment.pine       (valuewhen)
    statistics/ytd_year_to_date_percent_return.pine (valuewhen)

The nine scripts still failing are NOT engine gaps we papered over: they
reference variables never declared anywhere (`n`, `period`, `accdist`, `pvt`),
which TradingView also rejects, or are a plotting-less unit-test harness that
needs array methods beyond the current subset (`array.join`). Leaving them red
is the honest outcome — implementing a builtin only to watch a broken script
emit a plausible-but-wrong number would be worse than an accurate error.
